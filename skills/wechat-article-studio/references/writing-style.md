# 公众号写作与元数据规范

## 内容优先级

1. 读者真正学会一个概念或动作。
2. 证据准确且说明边界。
3. 文章容易读完、收藏和转发。
4. 标题和封面增强传播，但不透支信任。

## 正文风格

- 像长期研究同一主题的作者，不像通用知识助手。
- 先写人、物、动作、后果或一句当事人的话，再进入解释；不要把“定义一个概念”当作读者的进入理由。
- 用中文组织推理：先让读者看见发生了什么，再补事实、解释和判断。禁止把英文论文式“主张—分点论证—总结”直接翻译成中文成稿。
- 每段优先有一个可见的锚点：数字、物体、岗位、动作、对话、场景或后果。没有锚点的抽象判断应删除、合并，或改由具体材料承载。
- 从具体矛盾、数字或选择开始，避免“在当今时代”式开场。
- 一篇只回答一个核心问题。
- 原话用于提供证据，作者负责解释推理。
- 长短句交替；允许克制的第一人称判断。
- 少用整齐排比、连续反问、金句堆叠和机械总结。
- 把“像人写的”落实为作者的选择，而不是口语化装饰：敢删掉不服务问题的资料，敢指出证据能证明什么、不能证明什么；允许句子有停顿、有偏重，但每个判断都要落在材料上。
- 每一节只做一种推进：打开一个场景、补一条证据、解释一个机制，或修正一个读者直觉。不要把每节都写成“提出概念—三点展开—总结升华”的同形模块。
- “不是……而是……”整篇不超过三次。
- 不神化人物，不把个案包装成普遍规律。
- 历史数字必须写明年份和当时语境。
- 结尾给一个具体练习或判断问题，不喊口号。

## 去翻译腔检查

逐段朗读。出现以下信号即重写，而不是只替换同义词：

- 连续使用“这意味着”“换句话说”“值得注意的是”“从这个角度看”；
- 主语长期缺席，句子只剩抽象名词互相作用；
- 用“并非……而是……”代替真正解释；
- 段落像幻灯片标题的展开，读不出人物、空间或代价；
- 为了显得严谨而重复显而易见的边界说明。
- 一个段落放进任何科技主题都成立；这通常意味着它只是AI式概述，不是作者的观察。
- 整篇节奏过于匀称：每段近似长度、每节同样的三分法、每次转场都用相同连接词。

保留必要边界，但把它放在读者真正会误解的位置，并用正常中文说明。

## 平台语境

- 公众号读者先判断“这篇和我有什么关系、值不值得读完”；标题和前120字必须作为同一个承诺设计。标题直接说出读者真实的质疑、冲突或代价，首屏立刻给出至少一条可核验的具体事实，而不是把事实留到第二屏。
- 标题若使用“是不是”“还可信吗”“又一次失言了吗”一类争议问题，首屏必须先写最强的不利事实，再用一句有证据可回答的问题完成转场。不得用空泛反转替任何一方辩护，也不得把未证实的指控写成结论。
- 不以“马斯克为什么”“SpaceX 的故事”“关于火星”这类专题概述标题作为首选；优先测试能让目标读者代入的具体判断问题。标题不求悬念多，先求问题真、对象清、正文兑现。
- 视频号观众先判断“发生了什么、为什么反常、值不值得转给谁”；将完整机制、来源边界放入后段、评论置顶或关联文章，不能挤占首屏。
- 分享价值不是“请转发”。写出能帮读者向具体朋友解释一个误区、决策或见闻的句子。

## 标题候选

生成五种角度，不能只是替换近义词：

1. 误解纠正；
2. 具体冲突或数字；
3. 可获得的方法；
4. 反常识判断；
5. 现实应用。

推荐长度18—28个中文字符。人物名只在确实提升理解或识别时使用。
避免“震惊”“颠覆认知”“一定要看”等空洞刺激词。

选择标题时依次检查：

- 是否准确；
- 是否让目标读者看到与自己的关系；
- 是否留下一个正文能够兑现的信息缺口；
- 是否在朋友圈折叠后仍能理解。

## 描述

- 60—100个中文字符。
- 说明读者将理解什么、避免什么误区或学会什么动作。
- 不复述标题，不写“本文将带你”。
- 至少包含一个具体概念、案例或结果。

## 封面文案

- 4—10个中文字符，优先4—8字。
- 只表达一个视觉中心。
- 不使用标点堆叠，不使用完整长标题。
- 可与标题形成补充：
  - 标题解释问题，封面突出冲突；
  - 标题给方法，封面突出关键词。
