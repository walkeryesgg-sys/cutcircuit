# 爆款内容合同：从点击到自然分发

本页来自科技自媒体爆款样本的复盘。它是编辑推断与检查表，不是微信官方算法说明，也不保证阅读量。

## 先填四项

1. **真实张力**：读者已经感到的异常、损失、疑问或愿望是什么？不能只是“这个主题很重要”。
2. **首屏兑现**：哪一个可核验的数字、时间、场景、文件、动作或后果，能在前120字证明这个问题值得读？
3. **连续问题**：首屏之后，读者会依次追问什么？至少写三问。每一问必须比上一问更深，不能只是换一种说法重复主题。
4. **自然分享用途**：读者会把它发给哪一种具体的人，借此解释什么误区、帮助什么决策、表达什么共同感受？禁止把“请转发”当答案。

## 标题与首屏

- 标题命名一个真问题或反常结果；不要概述专题，更不能夸大未证实结论。
- 首屏用不利事实、具体代价或反常画面赢得阅读权；随后说明文章要区分的判断，不能用空泛反转留人。
- 好标题只打开问题，正文必须给出比标题更具体的回报。若读者读到第二屏还不知道自己会理解什么，重写。

## 正文：一屏一回报

正文不是资料清单。用下列循环推进，每次只选一种主动作：

`新问题 → 场景／事实 → 机制或因果 → 改变读者的一个理解`

- 每 2—4 段至少给一次可复述回报：数字、证据、对比、机制、反例、判断规则或人物选择。
- 每个小标题承担推进，而非给段落贴主题标签。小标题应隐含下一问，例如“他为什么没有继续做火星温室？”而不是“第二部分：SpaceX”。
- 关键判断使用证据阶梯：先放来源可追溯的事实，再解释其含义，最后才给作者判断；不能以形容词或情绪替代证据。
- 技术解释只保留服务当前问题的最小机制。先让读者看见反常结果，再解释原理；不要为了显得专业而复述整篇论文。

## 三种高留存故事骨架

### 1. 技术解释

`旧常识失灵 → 可见的反常数据／动作 → 一个关键机制 → 路线比较或现实影响 → 读者可用的新判断`

适合芯片、火箭、AI、产品机制。避免从定义和发展史开头。

### 2. 人物／公司

`突发事件或代价 → 此前目标 → 阻碍与选择 → 连锁影响 → 尚未解决的行业问题`

人物不是励志标签。写他想达成什么、做了什么、付出什么，最后把个体事件提升为读者能判断的结构问题。

### 3. 调查／服务决策

`读者的担忧 → 直觉答案 → 时间线、流程或多方证据 → 机制还原 → 风险边界与行动判断`

紧张感来自事实不断升级，不来自指控升级。涉及人物、公司、健康或争议时，严格区分已证实事实、各方说法与编辑推断。

## 情绪与自然分享

情绪是让人继续读和愿意发给他人的能量，不能脱离事实。优先选择一条主情绪，再给它一个具体落点：

| 情绪 | 内容落点 | 可分享的原因 |
|---|---|---|
| 好奇／惊讶 | 反常数据、动作、实验结果 | “原来事情不是我以为的那样” |
| 焦虑后的掌控感 | 成本、风险、误区与判断规则 | “这能帮你少踩一个坑” |
| 关切／不安 | 具体人、家庭或可感后果 | “这和我们有关” |
| 向往／身份认同 | 长期目标、艰难选择、可见进展 | “这解释了我为什么仍愿意相信它” |
| 公共讨论欲 | 合理的立场差异与未解问题 | “我想知道你怎么看” |

禁用愤怒、恐惧、优越感或群体对立来替代证明。结尾留下一个具体判断问题、行动清单或可转述结论；不命令读者点赞、转发。

## 对“算法推荐”的正确表述

- 可观察的分发前提是：读者愿意点击、继续阅读、收藏、评论或自然分享；标题—首屏不兑现会损伤后续阅读与信任。
- 这些是内容和读者行为的观察，不等于平台公开的权重公式。不得声称某个字数、发布时间、互动量或标题模板必然获得推荐。
- 新号先验证问题是否真实、首屏是否兑现、读者是否能说出一条收获和一个分享对象；将实际后台的打开率、读完率、收藏、评论、分享与新增关注分开记录。没有账号数据时，标注为待验证的编辑假设。

## 发布前快速审计

- 标题、首屏、第二屏能否组成同一承诺？
- 正文是否至少三次回答了新问题，而非重复换词？
- 每个核心判断是否有证据阶梯？
- 是否出现一个读者能看见的对象、代价或选择？
- 读者读完能否复述一个新机制或判断规则？
- 读者会自然发给谁，为什么？
- 删掉套路句后，文章是否仍有作者自己的观察和节奏？
