# Professional pre-production plan

Create this plan after requirements discovery and before production. Its purpose is to make the finished viewing experience reviewable while changes are still inexpensive.

## Required planning sequence

1. Define the audience, publication goal, viewing context, desired action, and one-sentence viewer promise.
2. Build a facts ledger separating verified fact, source claim, interpretation, prediction, and unknown.
3. State the thesis, central question, opening hook, final answer, exclusions, and factual framing.
4. Write the complete narration/dialogue script. Mark source-language audio separately with source identity and intended evidence function.
5. Divide the script into time-budgeted sections and beats. Give every beat one new narrative task.
6. Build the shot list. Map each spoken unit to picture content, shot purpose, source, framing, motion, captions, and transition.
7. Build the storyboard. Use images when available; otherwise use precise textual frames describing composition and action.
8. Plan voice, original sound, music, sound effects, silence, captions, watermark, intro, outro, and loudness hierarchy.
9. Inventory supplied and required assets. Identify gaps, sourcing constraints, provenance, rights risk, substitutes, and footage that must not be used.
10. Define aspect ratio, resolution, fps, codec, duration tolerance, cover variants, editable-source delivery, release score, and QA gates.
11. Record risks, fallbacks, unresolved assumptions, plan version, and approval request.

## Script standard

- Write the actual words, not a topic outline.
- Make the first spoken line complete and preserve it as canonical text for TTS and captions.
- Identify context before presenting a quotation whose pronouns or stakes depend on omitted material.
- Keep source quotations complete enough to preserve meaning; include verified source timecodes when known.
- End by answering the opening question in language the intended viewer can repeat.

## Shot-list standard

Use one row per spoken unit or coherent visual beat:

| Time | Audio/script | Shot and framing | Editorial purpose | Source/status | Motion/transition | Captions/graphics |
|---|---|---|---|---|---|---|

Every row must explain why that picture belongs with that line. Reject “科技素材”“相关画面”“后期找图” as final shot descriptions. Mark unresolved rows as explicit asset gaps with a fallback.

## Storyboard standard

Each panel must state:

- approximate time range and duration;
- visible subject, scale, placement, background, and crop;
- action or camera/graphic movement;
- subtitle, overlay, watermark, and safe-area behavior;
- entrance, hold, exit, and seam to the next panel;
- emotional or explanatory function.

Storyboard fidelity should match risk. A simple talking-head recut can use concise textual panels; a motion-heavy, multi-source, paid, or brand-critical video needs scene-by-scene panels and key-frame previews where practical.

## Approval gate

- Show the complete human-readable plan before requesting approval.
- Give it a version identifier and list unresolved assumptions visibly.
- Ask the user to approve that version, not merely the general topic.
- Record the approval statement verbatim in the machine-readable contract.
- Start production only when the approved version matches the current plan files.
- Increment the version and seek focused reapproval when a change affects thesis, script meaning, structure, runtime, visual treatment, source/rights posture, voice, brand identity, deliverables, or acceptance criteria.

Do not require reapproval for reversible implementation details that preserve the approved viewing experience.
